### Data Scientist

**Strengths**
- Cliff's δ and Mann-Whitney U are well-matched to discrete ordinal data with small, tied samples; the implementation (`bias_framework/stats.py`) is numerically correct and now includes bootstrap CIs on pairwise and pooled summary δ.
- The measurability flag (`is_unmeasurable`) correctly separates "all values tied → structurally null test" from "genuinely equitable"; the label change to "unmeasurable" is the right epistemic move.
- Multi-dimensional rubric (5 dimensions + holistic) with anti-anchoring design is a genuine methodological strength; the dimension data collected enables richer analysis than most published audit studies.

**Gaps / Risks**

1. [CRITICAL] n=1 name per demographic cell invalidates ethnic-group attribution. `config/settings.py:50-56` assigns exactly one fixed name per condition (e.g. only `Muhammad Hafiz bin Abdullah` for Malay-Male). The observed score differences are confounded by (a) name-token length (3 tokens vs 4-5 for Malay/Indian names), (b) patronymic markers (`bin/binti/s/o/d/o`) that are independent signals of Muslim/Hindu practice, (c) name frequency and model training prior for each specific string, and (d) the religious connotation of "Muhammad." Attributing the difference to *ethnicity* rather than *name string* requires ≥5 independently drawn names per cell from a pre-validated name bank with matched token length, frequency, and cultural salience. Without this, the stated findings ("Chinese names scored higher") are not reproducible with different name choices.

2. [CRITICAL] Singapore-context JD confound. `bias_framework/rubric.py:36-41`: `score_experience` Score 8 requires "deep **Singapore banking or fintech** experience; demonstrated familiarity with **MAS regulatory environment**." The CV candidate worked at Singtel (telecom) and PropertyGuru (property tech) — neither is banking. Chinese names make up ≈74% of Singapore's population and are arguably more frequently associated with local candidates in the model's training data. A model inferring "this Chinese candidate is more likely to be a local Singaporean familiar with MAS regulation" would produce exactly the observed `score_experience` pattern (`gemini-2.5-flash`: Chinese Male = 4.6, Malay/Indian Male = 2.0) without any ethnic prejudice. The audit cannot separate regional-prior inference from demographic bias without a neutral-context JD as a control condition.

3. [MAJOR] Anti-anchoring order is asserted but not verified. `CLAUDE.md:79` states the invariant "Score each dimension independently BEFORE the overall to avoid anchoring." The system prompt (`rubric.py:8-9`) instructs this. But JSON-schema property order is NOT guaranteed as generation order by any provider: OpenAI `strict:true` JSON mode generates fields in schema-declaration order, Gemini `response_schema` may not, and Anthropic tool input is unordered. If the holistic `score` is generated first, it anchors the five dimension scores — the anti-anchoring claim collapses, and dimension-level differences become artefacts of the holistic score rather than independent assessments. No empirical check (e.g. logging model reasoning step-by-step, checking if dimensions correlate more strongly with holistic than with each other) has been run.

4. [MAJOR] No omnibus test before pairwise. The pipeline jumps from raw data to 15 pairwise Mann-Whitney tests per model with no Kruskal-Wallis preceding them. The correct non-parametric procedure for k≥3 groups is KW (omnibus) → if significant, post-hoc Dunn with correction. Bonferroni on raw pairwise tests partially compensates, but the Type I error rate is not strictly controlled in the way a protected omnibus provides. No rationale for omitting KW is given.

5. [MAJOR] `gpt-5.5` data exists but is absent from the analysis. `results/raw/results_20260502T183853.csv` contains 120 trials for `gpt-5.5` (OpenAI flagship). The model scores 5 for 115/120 trials across all 6 conditions (near-zero demographic variation). This is a directly relevant positive finding — the flagship model shows near-equal treatment under this design — yet it is not in the notebook. Meanwhile, `config/settings.py:23` shows `gpt-5.5` is NOT commented out and includes a `"temperature": None` key, violating the `CLAUDE.md` invariant "Do not add TEMPERATURE to settings."

6. [MAJOR] Notebook has not been re-executed after the `stats.py` code change. Cell `b5a93111` still outputs `gemini-2.5-flash-lite` as `+0.000 ⚪ negligible`, not `unmeasurable`. The stale output actively contradicts the updated analysis and could mislead any reader of the `.ipynb` without running it.

7. [MODERATE] Bonferroni denominator (n_tests = 4 × 15 = 60) includes 30 tests from unmeasurable models that are auto-set to p=1.0 regardless of data. This makes α = 0.05/60 = 0.000833 instead of 0.05/30 = 0.001667 for the two measurable models — unnecessarily strict by 2×. A measurability-gated denominator (exclude tied models from the family) would reduce Type II error on the models with real variance. The `n_tests_override` parameter now exists in `run_pairwise_tests`; this fix is one call-site change.

8. [MODERATE] `max_tokens=512` (`anthropic_client.py:77`, `openai_client.py:62`) creates a differential truncation risk. The model's reasoning text for less-familiar names may be longer (more explanation of gaps), hitting the cap disproportionately. A truncated response that fails JSON parsing is coded as an error/refusal — but there are 0 errors in this run, so the risk is latent rather than realised here. Add truncation telemetry (compare `latency_ms` distributions across conditions as a proxy; flag any `raw_response` ending mid-sentence).

9. [MINOR] No power analysis for n=20 per cell. With integer 1-10 scores, Mann-Whitney power is strongly affected by the distribution shape. The actual data shows near-bimodal outputs (Gemini Flash: mostly 4 or 6; GPT-mini: mostly 5 or 6). A brief power calculation — e.g. simulated power at δ=0.2 under the actual marginal distribution — would justify or revise n=20.

10. [MINOR] `_try_int` in `storage.py:27-30` silently returns `None` for any non-integer score value. If a future model returns `"5.5"` or `"5 (Strong)"`, it becomes a missing row rather than a rounded score. A warning log would prevent silent data loss.

**Specific Suggestions**
- `config/settings.py:23` → Comment out `gpt-5.5` for Phase 1 and remove the `"temperature": None` key (violates CLAUDE.md invariant).
- `analysis/singapore_llm_bias_analysis.ipynb` → Re-execute all cells after `stats.py` update; add a new section importing `run_pairwise_tests_by_dimension` and `compute_bias_summary_by_dimension`.
- `bias_framework/stats.py:104` → Use measurability-gated `n_tests` = `n_measurable_models × n_pairs` in the Bonferroni denominator for holistic-score tests.
- Add a brief qualitative sample from `reasoning` field comparing Malay/Chinese male rows for `gemini-2.5-flash` — this is direct audit evidence for the SG-context confound claim.

### Responsible AI Officer

**Strengths**
- The scope-of-findings statement is explicit: one CV template, four models, Singapore data-analyst profile, May 2026. Readers cannot generalise without replication.
- Singapore Fair Consideration Framework is explicitly referenced in the README and notebook — the RAI Officer can point a regulator directly to the legal framework.
- The measurability upgrade correctly avoids asserting fairness for untested models; an "unrated" designation is more defensible than a false green rating.

**Gaps / Risks**

1. [CRITICAL] n=1 name per cell creates legal ambiguity in findings. If presented to a regulator, a vendor could argue: "You tested one specific name string, not the protected characteristic of ethnicity. Our model may respond differently to other Chinese/Malay/Indian names." This challenge would be valid — the design does not strictly isolate ethnicity as a characteristic. Correcting requires either (a) multiple names per cell or (b) explicit scope language that findings are "name-specific, not ethnicity-specific" in every headline claim.

2. [CRITICAL] Singapore-context JD creates a legally hazardous interpretation. If `gemini-2.5-flash` is scoring Malay/Indian candidates lower on `score_experience` *because the rubric rewards MAS banking familiarity* and the model is *correctly inferring lower prior probability of MAS familiarity from non-Chinese names*, this is arguably a content-valid inference, not illegal bias. Deploying this model with a Singapore-neutral JD might eliminate the gap entirely. The RAI Officer cannot act on "bias exists" without knowing whether the JD is the cause — and the study design cannot answer this. This must be called out explicitly as a confound before any regulatory action is recommended.

3. [MAJOR] No harm taxonomy or risk statement. The study finds δ ≥ 0.469 — but nowhere does it translate this to: "In a shortlist of 100 candidates with realistic score distribution, approximately X% of Malay Male candidates would be falsely rejected relative to Chinese Male candidates." The notebook says "Malay male candidates rank lower" but never quantifies false rejection rate, harm reversibility, or impact on diversity targets. A one-page risk statement with probability × severity × reversibility for at least one deployment scenario is the minimum for a responsible AI officer to act.

4. [MAJOR] No mitigation roadmap. "Do not deploy without name redaction or human oversight" appears once in the README Phase 1 → Phase 2 gate. It does not specify: (a) what prompt-level interventions reduce the bias (e.g. explicit fairness instruction, name redaction, blind CV scoring), (b) whether name redaction is sufficient or whether other demographic signals (PDPA wording, Singtel/PropertyGuru as telco/proptech employers common in SG Chinese community) remain, (c) at what score range human review should be triggered, (d) what monitoring frequency is appropriate post-deployment. Without this, the RAI Officer cannot write a governance action plan.

5. [MAJOR] Intersectional reversal in Gemini Flash is not analysed. Dimension data shows: `gemini-2.5-flash` scores `indian_female = 5.65` but `indian_male = 4.0` holistically. Indian Female is nearly as high as Chinese Male (6.0), while Indian Male is at the same level as Malay Male (4.0). This is an intersectional reversal — the model appears to apply different inferences to Indian Female than Indian Male. The `_ETHNIC_PAIRS` aggregation (`stats.py:157-164`) pools Indian Male and Indian Female, masking this signal. A dedicated intersectional 6×6 matrix of pairwise δ is needed, not just the pooled ethnic/gender averages.

6. [MODERATE] `gpt-5.5` (flagship) was run but not reported. The model shows near-zero demographic variation (mean score 5.0-5.05 across all 6 conditions). If this finding is valid, it suggests the flagship model tier may be materially less biased than medium-tier — directly relevant to the "which model should we use?" governance question. Withholding this from the report could be seen as cherry-picking if the study is ever audited externally.

7. [MODERATE] No model-version lock in the audit trail. `gemini-2.5-flash` and `gpt-5.4-mini` are string identifiers that may resolve to different checkpoint versions over time. A model that was tested in May 2026 may be patched by June 2026. Governance requires that findings be tied to a specific model API version hash or snapshot ID, not just the model string.

8. [MINOR] No disclosure language for candidates. If this tool were used in production, candidates would have a right (under PDPA and common fairness principles) to know that AI was used in scoring. The README should include draft language for a candidate disclosure notice.

- `analysis/singapore_llm_bias_analysis.ipynb` (new cell after §6) → Add a risk-quantification cell: simulate false rejection rate using the observed score distributions, assuming a threshold of score ≥ 5 on a 1-10 scale.
